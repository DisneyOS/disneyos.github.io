# DisneyOS Design System

> **A clean, intelligent interface designed to reduce friction and keep guests focused on enjoying the parks.**

---

# Design Philosophy

DisneyOS should feel calm.

It should never overwhelm the user with information.

Every screen should answer one question:

> "What is the most useful thing for the user to know right now?"

---

# Core Principles

## One Glance

Users should understand the current situation within three seconds.

---

## Context Over Navigation

Bring information to the user instead of making the user search for it.

---

## Calm Technology

Only show what matters.

Hide everything else until it becomes relevant.

---

## Consistency

Every card, button, spacing rule, animation, and icon should feel familiar.

Users should never wonder how something works.

---

# Visual Style

DisneyOS combines inspiration from:

- Apple iOS
- visionOS
- Dynamic Island
- Apple Weather
- Apple Wallet
- Home Assistant

The interface should feel native on iPhone.

---

# Color Palette

## Primary

Disney Blue

Used for navigation and primary actions.

---

## Success

Green

Reservations confirmed.

Ride available.

Completed actions.

---

## Warning

Amber

Approaching reservation.

Weather alerts.

Temporary downtime.

---

## Critical

Red

Ride closed.

Reservation expiring.

Urgent notifications.

---

## Background

Near Black

Very dark gray.

Not pure black.

---

## Cards

Dark elevated surfaces.

Rounded.

Soft shadows.

# Typography

Large Title

Section Titles

Headline

Body

Caption

Use Apple's SF Pro whenever available.

---

# Layout

8-point spacing system.

Consistent margins.

Maximum readable width.

Large touch targets.

Thumb-friendly navigation.

---

# Components

Every interface is built from reusable components.

Examples:

- Information Card
- Metric Card
- Status Badge
- Park Card
- Reservation Card
- Attraction Card
- Navigation Bar
- Floating Action Button

---

# Cards

Cards are the primary building block.

Each card should contain:

- Icon
- Title
- Primary Information
- Secondary Information
- Optional Action

---

# Icons

Use Material Design Icons where possible.

Icons should communicate meaning without text.

---

# Animations

Animations should be subtle.

Examples:

- Fade
- Slide
- Scale
- Gentle pulse

Avoid distracting animations.

---

# Notifications

Notifications should be actionable.

Examples:

"Walk toward Haunted Mansion."

"Order lunch now."

"Lightning Lane in 20 minutes."

---

# Accessibility

Support:

- Large text
- VoiceOver
- High contrast
- Reduced motion
